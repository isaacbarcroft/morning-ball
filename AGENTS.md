# morning-ball — Claude Code conventions

## Stack
- Expo SDK 55, RN 0.83, Expo Router, NativeTabs (when added)
- MobX + mobx-react-lite, MVC architecture
- Supabase (Postgres + phone OTP + Realtime + Storage + Edge Functions)
- expo-notifications for push
- TypeScript strict, Vitest + Maestro

## Hard rules (enforced by ESLint where possible)
1. **No `any`.** Use `unknown` and narrow.
2. **No `else` blocks.** Early return.
3. **No control-flow ternaries** (no nested, no side-effecting). Ternaries only for simple value selection.
4. **`runInAction` after every `await`** that mutates state.
5. **`logger.*` over `console.*`.** `console.*` is banned outside `src/services/logger.ts`.
6. **Interfaces over types** for object shapes. `as const` over `enum`.
7. **MVC.** Views import from controllers; controllers orchestrate stores + services.
8. **No `useEffect` for data loading.** Controllers + MobX reactions instead.
9. **Filenames:** `kebab-case.ts` / `kebab-case.tsx`.
10. **Yarn, not npm.** EAS commands stay verbatim; everything else uses `yarn add`.

## Key paths
- `src/app/` — Expo Router routes (file-based)
- `src/views/` — reusable UI components
- `src/controllers/` — business logic
- `src/stores/` — MobX state
- `src/services/` — `supabase`, `logger`, `push`
- `src/lib/` — `theme`, `constants`, `validation`, `format`
- `src/types/database.ts` — generated by `supabase gen types`
- `supabase/migrations/` — numbered SQL migrations
- `supabase/functions/` — edge functions
- `__tests__/` — Vitest (controllers, stores, lib)
- `e2e/` — Maestro flows

## Workflow
- Lint: `yarn lint`
- Type-check: `yarn typecheck`
- Test: `yarn test`
- Boot: `yarn start` (dev build only — Expo Go is not supported)
- Migrations: write to `supabase/migrations/`, then `npx supabase gen types typescript --project-id <id> --schema public > src/types/database.ts`

## Auth state
- Phone OTP via Supabase. Test-OTP mode in development; Twilio + A2P 10DLC for production.
- Push token registration happens at OTP verify (M2), not later.
